# Discovery source contracts

Every adapter returns independent candidates and structured source errors. Imported statements are unverified evidence; they do not authorize execution, assign trust, or register an agent. Discovery never calls tools, starts containers, runs a process, clones a repository, or reads an arbitrary local path. Runtime OpenTelemetry observations enter the separate runtime pipeline.

The request envelope is `{"sources":{"a2a":[...],"mcp":[...],"kubernetes":[...]}}`. Source items are processed independently, with at most 1,000 top-level items per source, 1,000 objects per inventory, 100 skills/tools per candidate and ten MCP tool pages. Network operations use the same explicit endpoint policy, TLS verification, DNS pinning, response-size limit and timeout boundary as routing. HTTP redirects are rejected. Read-only GETs may retry; protocol POSTs do not retry automatically.

| Source | Supplied item | Live discovery | Deliberate limits |
|---|---|---|---|
| `a2a` | `{"card":{...}}` | `{"url":"https://agent.example/.well-known/agent-card.json"}` fetches that exact card URL | Validates required core fields; understands legacy 0.3 and current `supportedInterfaces`. No task calls, authenticated extended-card fetch, signature verification or full-spec conformance claim. |
| `mcp` | `{"inventory":{"serverInfo":{"name":"tools","version":"1"},"protocolVersion":"2025-11-25","tools":[{"name":"lookup","inputSchema":{"type":"object"}}]},"endpoint":"https://tools.example/mcp"}` | `{"url":"https://tools.example/mcp"}` initializes, sends initialized notification and lists all bounded tool pages | Only 2025-11-25 sessionless JSON HTTP. Rejects a different negotiated version, malformed envelope, repeated cursor or oversized inventory. No stdio execution, OAuth, session-ID propagation, SSE or 2026 modern requests. |
| `kubernetes` | `{"items":[{"kind":"Pod","metadata":{"name":"worker","namespace":"team","uid":"uid1"}}]}` | `{"api_url":"https://cluster.example","namespace":"team","kinds":["Service","Deployment"]}` lists explicitly selected resource kinds in that namespace | Reads only Pods, Deployments, Services, Ingresses and ServiceAccounts; emits selected metadata and service-account name. Does not retain environment, command lines, secrets or ConfigMaps. No credentials configured by this adapter. No watch, pagination or EndpointSlice collector: continuation responses are rejected as partial. |
| `docker` | `{"containers":[{"Id":"id1","Names":["/worker"],"State":"running","Labels":{}}]}` | `{"api_url":"https://docker.example"}` GETs `/containers/json`; native arrays or a `containers` wrapper are accepted | Explicit configured HTTP endpoint only. No Unix/named pipe socket, socket mounting, inspect calls, environment or command import. Docker list authorization is supplied by deployment networking; adapter has no credential passthrough. |
| `api_registry` | `{"entries":[{"id":"service1","name":"Analyst","endpoint":"https://example/run","protocols":["http"],"service":"analyst"}]}` | `{"url":"https://registry.example/inventory"}` fetches one explicitly specified JSON page | Also understands official MCP `servers:[{server:{...}}]` wrappers and first remote endpoint. Package-only records stay metadata without callable endpoint. No automatic pagination, package install, liveness claim or credentials. |
| `git` | `{"manifest":{"id":"manifest1","name":"Analyst","endpoint":"https://example/run","skills":["security"]}}` | None | Manifest-only import; `path`, `file`, `command` and `clone_url` are rejected. No filesystem/repository scan. The caller is responsible for obtaining an authorized manifest. |
| `local_process` | `{"id":"process1","name":"worker","framework":"langgraph","service":"analyst"}` | None | Supplied process inventory only; no process scanning, process arguments, environment or execution. |
| `manual` | `{"name":"Candidate","endpoint":"https://example/run","skills":["security"]}` | None | Unauthoritative candidate metadata. Supplied registration IDs, trust assertions, arbitrary evidence and metadata are ignored. |

Kubernetes opt-in annotations are `agent-census.io/name`, `endpoint`, `protocol`, `framework`, `owner` and `deployment` under that prefix. The service correlator reads the `app.kubernetes.io/name` label. These are project conventions, not Kubernetes or A2A standards. Docker conventions use `agent-census.name`, `.endpoint`, `.protocol`, `.framework`, `.owner`; `com.docker.compose.service` supplies service identity. These declarations strengthen inventory links, not verified identity.

A2A cards require name, description, agent version, capabilities object, default media arrays, and skills with id, name, description and tags. Current interfaces carry URL, binding and protocol version. For gRPC-only cards the catalog retains the profile evidence without a callable HTTP endpoint. Cryptographic card-signature verification is unsupported; no verified identity is inferred. Protocol version and binding evidence survive registry normalization so routing can fail closed on unsupported profiles.

Useful primary references: [A2A schema](https://github.com/a2aproject/A2A/blob/main/specification/a2a.proto), [MCP registry model](https://github.com/modelcontextprotocol/registry/blob/main/pkg/model/types.go), [Kubernetes EndpointSlices](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/). A live API is implemented only where the table says so; no real cluster, Docker daemon or private registry has been configured or validated in this deliverable.
